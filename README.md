# DeltaDraft

A real-time League of Legends draft analysis and recommendation tool.

## Core Architecture

The project is a decoupled system. The architecture differs between the web version and the desktop application.

### Desktop Application Architecture

1.  **Frontend (Electron Application)**: The desktop application is a self-contained program. It runs on the user's machine, connects to the live League of Legends client (LCU), and fetches statistical data directly from a public Cloudflare R2 bucket. All data processing and calculations happen client-side.

2.  **Data Storage (Cloudflare R2)**: A publicly accessible S3-compatible object storage bucket. It hosts the static JSON datasets generated by our data pipeline. The public URL is `https://pub-1efd88d862814361909e5510d7af1c1a.r2.dev`.

3.  **Data Pipeline (GitHub Actions)**: An automated, scheduled process that scrapes the latest data from LoLalytics, processes it, and uploads it to the Cloudflare R2 bucket for the desktop client to consume.

### Web Version Architecture

1.  **Frontend (Web Browser)**: A standard web frontend that makes API requests to the Vercel backend.
2.  **Backend (Vercel Server)**: A serverless Python Flask API hosted on Vercel. It serves as a middleman, fetching data from R2, processing it, and returning the analysis to the web frontend.
3.  **Data Pipeline (GitHub Actions & Cloudflare R2)**: The same data pipeline and storage used by the desktop application.

## Technology Stack

-   **Frontend**: Electron, HTML, CSS, JavaScript (no framework)
-   **Backend (Web-only)**: Python (Flask), Vercel (hosting), Gunicorn (web server)
-   **Data Pipeline**: Python, GitHub Actions (automation), Cloudflare R2 (S3-compatible object storage)

## Component Breakdown

### 1. Frontend (Electron App)

-   **Location**: `/desktop-app/`
-   **Description**: A desktop application built with web technologies. It is the only component the end-user interacts with directly. It fetches data directly from Cloudflare R2.
-   **Key Files**:
    -   `index.html`: The main UI and all client-side application logic, including data fetching from R2 and algorithm execution.
    -   `main.js`: The Electron main process. Handles window creation, LCU connection, and secure file system access for settings/favorites.
    -   `preload.js`: Securely exposes backend functions from `main.js` to the `index.html` frontend.
    -   `package.json`: Defines dependencies and build scripts.

**To Run Locally:**

```bash
cd desktop-app
npm install
npm start
```

**To Build Installer:**

```bash
cd desktop-app
npm run dist
# Installer will be in /desktop-app/dist/
```

### 2. Backend (Vercel Server - for Web Version)

-   **Location**: `/backend/`
-   **Description**: A Python Flask API that serves data from Cloudflare R2. **It is NOT used by the desktop application.** It is deployed as a serverless function on Vercel for a potential web version.
-   **Key Files**:
    -   `server.py`: The Flask application. Contains all API endpoints and logic for fetching and caching data from R2.
    -   `vercel.json`: Vercel's configuration file.
    -   `requirements.txt`: Python dependencies for the server.
-   **Deployment**: Pushing a commit to the `main` branch on GitHub will trigger a new deployment on Vercel.

### 3. Data Pipeline (GitHub Actions)

-   **Location**: `/backend/scripts/` and `/.github/workflows/`
-   **Description**: This system automatically scrapes data from LoLalytics and uploads it to the Cloudflare R2 bucket. It runs on a schedule, requiring no manual intervention.
-   **Key Files**:
    -   `backend/scripts/scrape_lolalytics.py`: The Python script that performs the scraping and uploads the data to R2.
    -   `.github/workflows/update_data.yml`: The GitHub Actions configuration file. Defines the schedule (`cron: '0 6,18 * * *'`) and the steps to run the scraper.
-   **Manual Trigger**: You can run the data update job manually via the "Actions" tab on the GitHub repository.

## Key Credentials & Environment Variables

DO NOT COMMIT SECRET KEYS TO THE REPOSITORY.

### For the Data Pipeline (GitHub Actions):

These are required for the scraper to upload data to R2.

-   **Location**: GitHub Repo -> Settings -> Secrets and variables -> Actions
-   **Secrets Needed**:
    -   `CLOUDFLARE_ACCOUNT_ID`
    -   `AWS_ACCESS_KEY_ID`
    -   `AWS_SECRET_ACCESS_KEY`

### For the Backend Server (Vercel - Web-only):

These are required for the server to read data from R2.

-   **Location**: Vercel Project -> Settings -> Environment Variables
-   **Variables Needed**:
    -   `CLOUDFLARE_ACCOUNT_ID`
    -   `AWS_ACCESS_KEY_ID`
    -   `AWS_SECRET_ACCESS_KEY`

## Development Workflow

-   **To Update the UI or Frontend Logic**:
    1.  Modify files in `/desktop-app/`.
    2.  Test locally using `npm start`.
    3.  When complete, build a new installer with `npm run dist` and distribute the new `.exe`.

-   **To Update the Backend API Logic (Web-only)**:
    1.  Modify files in `/backend/`.
    2.  Test locally by running the local Python server.
    3.  Commit and push to `main`. Vercel will redeploy automatically.

-   **To Update the Data Scraper**:
    1.  Modify `backend/scripts/scrape_lolalytics.py`.
    2.  Commit and push to `main`. The next scheduled GitHub Action will use the new script.
